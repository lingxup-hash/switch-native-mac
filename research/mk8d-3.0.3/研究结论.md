# 马里奥赛车8豪华版 3.0.3：Mac 原生路线可行性研究

日期：2026-10-22。范围：用户现有 3.0.3 的离线程序分析、Mush8 接口审查、开源转换工具筛选。未执行游戏代码，未改动游戏、存档或 Mush8 源码；未安装转换工具。

## 结论

有值得做小规模实验的路线：Remill AArch32/Sleigh → LLVM IR → Apple ARM64 原生代码，加上保留 32 位访客语义的运行支持层。现有源码证明它不是纯理论设想，但尚未完成本机转换执行，更没有证明整游戏可运行。不能把 LLVM IR、反汇编成功或模拟器运行叫作原生游戏交付。

无需立即获取不同游戏版本就能开展这个实验。现成 Mush8 不能直接接收结果：它目前是 ARM64 指令改写/直执行环境，不是通用跨架构转换器。

## 本机证据

输入目录：`/Volumes/SwitchNative/Builds/Mush8/compat-3.0.3/exefs`。可复现脚本 `inspect_modules.py`，输出 `module-inventory.json` 含各模块 SHA256。

- NPDM Flags0=0x04，64 位指令标志为 false。
- 四个模块的动态符号条目尺寸 DT_SYMENT 均为 16 字节，按 ELF32 解析，符号名称越界数均为 0。
- main BID=6A85262F21B90364；实际代码片段 0x8FD7F0 包含 mov、cmp、movweq、add、pop pc，ARM32 解码成功。

## Mush8 必须跨过的接口

审查版本：9f6e2b7c3cdbac4bde3c1878ea6978cc85476067。

1. `crates/nxpatch/src/classify.rs:28` 固定 ARM64 解码器。
2. `crates/nxfs/src/nso.rs` 的 symbols() 按24字节 ELF64 符号解析，不能直接用于上述16字节 ELF32 表。
3. `crates/nxhost/src/loader.rs:161` 起只处理 R_AARCH64 重定位，向64位地址槽写值；需要 ELF32/ARM 重定位实现。
4. `crates/nxhost/src/stubs.rs` 捕获 x0–x7/d0–d7；需要 ARM32 参数、栈、返回值与回调适配。
5. `crates/nxhost/src/mem.rs` 分配39位地址空间；32位访客指针必须保留自己的地址语义，不能直接当作宿主指针使用。
6. `crates/nxhost/src/nvn/objects.rs` 直接读宿主地址与固定对象布局；需要逐项验证32位 SDK/NVN 的结构偏移、对象尺寸、回调与图形API桥接。已有 Metal 后端可能复用，接口层不能假定兼容。

同时需恢复间接跳转/函数指针目标，并处理 TLS、线程、原子操作、异常展开、SVC/IPC。main 的 __aeabi_unwind_cpp_pr0/pr1 导入是 ARM 异常展开相关证据。

## 工具筛选

- **Remill：首选实验候选。** 当前有 AArch32/Sleigh 解码和 lifting，tests/Thumb/TestLifting.cpp 有 ARM literal-load 及 ARM/Thumb 测试，bin/lift/Lift.cpp 支持原始指令字节输入。ARMBase.cpp 的默认 triple 仍为 ARM/Thumb，DataLayout 为32位指针，因此必须正确处理跨架构输出和运行支持，不能仅替换 triple 就宣称成功。AArch32 Runtime 还定义了不支持指令的模拟回退；实验必须检查并拒绝以它掩盖转换缺口。
- **rev.ng：备选分析工具。** 支持 ARM 输入；公开 recompile 成品路线是 Linux x86-64，并非现成 Mac ARM64 移植方案。
- **McSema：不优先。** 项目已归档，公开支持列表没有 ARM32；“32位”不能泛指所有32位架构。
- **BinRec：不匹配。** 公开支持环境为 Linux x86，不能直接承担本次 Switch ARM32 转换。

# 旷野之息性能与缓存排查

以下来自本次1.6.0原生版实测，不保证其他版本相同。

## 帧率低与突然停顿分开看

- 曾开启30＋30补帧，但日志插值帧为0；游戏被限制约30帧。关闭后瞬时恢复100FPS，仅说明限帧解除。
- 跑动中37条新管线编译耗时约967毫秒，另有整帧1.55秒。正常GPU绘制约7–11毫秒，说明这些大停顿主要在现场编译，降低分辨率不能消除全部停顿。
- 平均FPS会掩盖长帧。记录帧时间p50/p95/最大值、新建管线/着色器耗时和同路线重复结果。

## 缓存不会每次清空

一次重启预热约4.4秒，准备2413条渲染管线；另一次累计10000次建管线有8551次读取存档。启动时数字重新增长，可以是重建运行对象和读取磁盘缓存，不等于重新编译全部内容。

缓存没有固定“满格”。新区域、特效与材质组合仍可能产生新变体。不建议把清空缓存当作常规提速方式。

本机补编译过101个新记录库：编译、Metal加载、测试应用签名通过；测试副本尚未完成同路线游玩对照。因此用户后来反馈变顺，不能自动归因于这101个库。

## 穿模与闪退

腿部下陷会随地点变化；上游有类似未解决记录，尚未完成30帧／高帧率同位置对照。不能把补缓存当成穿模修复。

历史一次SIGABRT来自渲染编码阶段2秒超时；调试暂停是候选原因，不是已证实唯一原因。另一次金手指连接期间出现SIGUSR2后进程退出，根因未定。发生退出时先保留日志和存档，不要重复快速点击修改按钮。

## 最小对照流程

1. 保存并备份，记录版本、构建提交、启动方式和设置。
2. 关闭补帧，在同一存档、路线和镜头下记录日志。
3. 重复同路线，比较新编译耗时与长帧，而不只看一个FPS截图。
4. 再单独改变帧率上限或分辨率；兼容启动模式也应独立对照。
5. 发布结论时写清是否更换了应用、是否冷缓存、是否实际完成游玩。

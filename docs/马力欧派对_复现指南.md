## 2. 环境与独立目录

记录中的主机为Apple Silicon Mac mini M4、16GB内存，macOS 27.2、Xcode 27.2 beta 2；这是作者测试环境，不是经过验证的最低系统要求。需要完整Xcode/Metal工具链、上游所要求的.NET和SPIRV-Cross等工具；Python需要lz4、capstone、fonttools，3.14以前还需相应zstd支持。依赖清单以固定提交的[上游开发说明](https://github.com/seedds/nxnative/blob/ebe75c9d5d34486f714678f850f0e74bbab398ac/docs/development.md)为准。

工作目录使用支持符号链接的APFS卷。作者把APFS磁盘映像放在ExFAT移动盘上，再在挂载的APFS卷内构建；不要把ExFAT物理盘路径与APFS挂载路径混淆。

以下四段命令按顺序在同一个 Bash 会话或脚本中执行，变量需要保留；先替换全部占位路径。启用失败即停止，避免构建失败后继续复制旧host。`GAME_INPUT`必须是自己准备的本体/更新NSP独立目录。不要指向正在由另一位协作者构建的目录，也不要在示例中填写或输出密钥内容。

```bash
set -euo pipefail
WORK='/absolute/path/to/isolated-work'
GUIDE='/absolute/path/to/switch-native-mac'
GAME_INPUT='/absolute/path/to/your/Jamboree-inputs'
KEYS='/absolute/path/to/your/prod.keys'
GAME_ID='0100965017338000'
mkdir -p "$WORK"
git clone --branch jamboree-nro https://github.com/lingxup-hash/nxnative.git "$WORK/nxnative"
git -C "$WORK/nxnative" checkout --detach 3c88be9e109802fbf76bb9084c04a5c12d059f1f
```

该提交已含两个补丁，**不要再重复应用**。若研究补丁本身，先从集成点`abf17c8…`开始，在单独副本中依次检查和应用`0001`、`0002`；不要把这两个补丁直接打到缺少#89/#90/#91的裸基线。

## 3. 先生成完整资料，再派生诊断profile

在准备好的Python环境中，使用独立源码与独立输入目录：

```bash
cd "$WORK/nxnative"
python scripts/build_ipa_from_nsp.py "$GAME_INPUT" -k "$KEYS" --platform mac --progress lines
```

首次流程可能会执行启动堆检查；默认临时profile在本游戏上曾中止，不能把命令结束或提示“done”解读为游戏可玩。检查实际日志、Build ID、提取目录、139个NRO和着色器结果。固定版本历史记录中25693个着色器有3个失败，仍是待处理问题。

`game_va64.tsv`不是完整profile目录：它还依赖当前游戏生成的着色器映射及其它表。复制**整个生成profile**，再替换其中`game.tsv`；诊断目录应为新目录，已存在时先检查其来源，勿盲目覆盖。

```bash
B="$GAME_INPUT/${GAME_ID}_build"
test ! -e "$B/profile_va64" || { printf '%s\n' '诊断目录已存在，请先核对，停止。'; exit 1; }
mkdir -p "$B/profile_va64"
cp -R "$B/profile/$GAME_ID" "$B/profile_va64/$GAME_ID"
cp "$GUIDE/profiles/mario-party-jamboree/game_va64.tsv" "$B/profile_va64/$GAME_ID/game.tsv"
DM_GAMES_DIR="$B/profile_va64" DM_GAMES_FIRST=1 make -C "$WORK/nxnative/dm/host" GAME="$GAME_ID" dmhost
cp "$WORK/nxnative/dm/host/dmhost" "$B/tools/dmhost_va64"
```

布局：总预留64.75GiB，alias64.125GiB，stack256MiB；host另有256MiB前缀，余下heap128MiB。它针对启动时56GiB虚拟地址请求，**不是需要64GiB物理内存**。不要同步把`app_pool`改成64GiB，也不能把这个Mac诊断布局直接视为iOS方案。

## 4. 使用独立存档启动

在游戏退出后准备测试存档。第一次测试可用空目录；若要对照同一存档，复制自己的存档到新目录，不直接让实验版修改唯一副本。

```bash
mkdir -p "$B/diag/save" "$B/diag/temp" "$B/run"
cd "$B/run"
env DM_ROOT="$B" DM_ROMFS="$B/extract/v393216/RomFS" \
  DM_SAVE="$B/diag/save" DM_TEMP="$B/diag/temp" \
  DM_MSL_DIR="$B/shader/cache" DM_FONT_DIR="$B/font" \
  DM_NVN_SHMAP="$B/profile_va64/$GAME_ID/shader_map.tsv" \
  DM_LANG=en-US DM_WINDOW=1 DM_AUDIO=1 \
  "$B/tools/dmhost_va64" "$B/patched_v393216" > "$B/diag/manual-run.log" 2>&1
```

示例日志名会被重用；保留多次运行时请自行换名。这里有意显式选择`dmhost_va64`和`profile_va64`，避免把默认5GiB的host当作诊断版。

## 5. 产物一致性与交付边界

- 更改着色器翻译链后，上游要求更新chain版本并重建受影响的着色器、映射表与host；不能只拿新host配未知旧缓存，也不要手改版本号来绕过检查。
- 每次记录源码提交、未提交diff摘要、profile哈希、Build ID、编译器版本、shader chain版本、运行命令和退出原因。日志/截图保留在本机，发布时仅分享必要且脱敏的诊断内容。
- 本仓库当前没有一键安装包。完成全新环境构建、小游戏和多人验证前，不标为“完整可玩”。具体门槛见[验收清单](马力欧派对_验收清单.md)。

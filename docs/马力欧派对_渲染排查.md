# 马力欧派对：渲染排查与证据模板

## 已有观察与尚未证明的推断

作者记录中：标题和角色头像等2D内容正常；角色选择上方的3D预览出现大块纯色平面；另一次后台截图能看到正常广场。**这涉及不同场景，不能据此认定焦点切换导致渲染异常，也不能证明全部3D路径正常。**

日志中的cube纹理类型不匹配、uniform buffer缺失和sampler未登记提供了线索，但仅按告警数量无法确定哪一项导致该画面。较早构建另有3个subgroup相关着色器失败；是否用于异常角色，尚需关联具体绘制调用。

## 最小对照顺序

1. 固定Build ID、host提交、profile、shader chain、存档、分辨率、语言和角色。不把多个试验补丁同时加入基线。
2. 在同一角色选择画面停止按键，记录前台→后台→前台的截图与时间；另记当前菜单/场景，避免把场景切换当作焦点对照。
3. 对异常帧定位绘制角色的pass/draw：记录顶点/片元shader标识、顶点/索引缓冲区、布局与stride、实例数量、uniform buffer绑定、纹理类型及sampler。
4. 若角色顶点已经被错误变换，优先检查投影/视图、骨骼矩阵、UBO偏移/范围和顶点格式；若几何正常而材质异常，再追贴图视图、cube/array类型、采样器和资源生命周期。以上是排查分支，不是已确认根因。
5. 把每条告警关联到上述draw；统计/性能查询的未实现告警单列，避免淹没真正影响画面的错误。

## Subgroup转换的验证边界

“MSL编译成功”只是第一道门槛。若将subgroup行为简化为single-lane常量，需证明所涉及操作、stage和活动lane条件符合该替代的语义；不能把所有mask/ballot简单视为零或一就宣称正确。

保留失败shader的标识与本地SPIR-V/MSL供定位；公开仓库可放自行编写、无游戏内容的最小测试用例，覆盖常量分量读取、越界/不支持形式、不同mask和stage。验证不只看退出码，还看输出值与实际画面对照。未证明语义的降级要明确标为实验。

建议先证明角色预览修复，再验证一个完整小游戏和返回菜单。不要用降低告警数量、显示FPS或进入标题代替这些验证。
